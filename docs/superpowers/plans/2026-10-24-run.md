# Run Configurations and Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Choose a run configuration for the open folder, build what it names, start its program with the launch profile's arguments and environment, watch its output in a Run window, stop it, and open its browser once it listens.

**Architecture:** `rsharp-core`'s new `run` module owns the model: launch profiles, configurations, plans, the browser readiness wait and console links — all testable without a build. The window builds the list from its evaluated projects, keeps the chosen name with the folder, resolves a plan off the UI thread (MSBuild's `-getProperty`), builds through the existing build controller, and starts the program through `process::spawn`, streaming into a second console view.

**Tech Stack:** Rust 2024, serde/serde_json_lenient, std threads and channels, existing `process::spawn`, gpui 0.2.2. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-24-run-design.md`.

## Global Constraints

- Every program starts through `rsharp_core::process::spawn`; the browser is the one exception and says why.
- Non-UI crates have no gpui dependency; the UI never blocks on a process, MSBuild or a socket.
- Colours are `theme.rs` tokens; every visible change is checked with `just screenshot`.
- Tests are offline where they can be, use isolated CLI homes and cleared NuGet sources, and skip saying why when the SDK is missing.
- A `// shortcut:` marks every limit taken on purpose (console input, the folder's own configurations).

## Review Focus

1. Stop and workspace change must end the program's whole tree and release every waiter (Tasks 5, 6).
2. A failed build, a failed save or a refused plan must start nothing and say why (Task 5).
3. Ports, hosts and paths with parentheses, wildcard hosts and relative working folders must resolve as Passenger resolves them (Tasks 1–3).
4. A second Run must not start a second program, and Reuse of a finished one must rerun the same configuration (Task 6).
5. The browser must never open on a refused connection, and never keep the window waiting (Tasks 4, 6).

### Task 1: Launch profiles and the command line

**Files:** create `crates/rsharp-core/src/run/mod.rs` (module docs, re-exports), `run/profile.rs`, `run/command_line.rs`; export in `src/lib.rs`.

**Interfaces:** `run::profile::LaunchProfile { name, command, executable_path, command_line_args, working_directory, environment_variables, application_url, launch_browser, launch_url }` with `read(project_folder: &Path) -> Vec<LaunchProfile>`, `unsupported(&self) -> Option<String>`, `runs_project(&self) -> bool`, `environment(&self) -> BTreeMap<String, String>`, `browser_url(&self) -> String`, `settings_path(folder: &Path) -> PathBuf`. `run::command_line::split(&str) -> Vec<String>`.

- [x] Acceptance tests: a profile of each kind reads its values; a file with comments and trailing commas reads; a missing or unreadable file gives an empty list; `ASPNETCORE_URLS` is set from the first application URL unless the profile sets it; `launchUrl` joins its base URL and an absolute one is kept; every unsupported command names its reason in Rider's terms; a command line splits as .NET splits one, quotes and backslashes included.
- [x] Implement, run `cargo test -p rsharp-core run::`, and confirm the tests fail before the code and pass after.

### Task 4: The browser and the console's links

**Files:** create `crates/rsharp-core/src/run/browser.rs`, `run/link.rs`.

**Interfaces:** `browser::address(url: &str) -> Option<Url>` (scheme http/https only, `*`/`+` host read as `localhost`); `browser::shown(&Url) -> String` (a wildcard host shown as `localhost`); `browser::not_responding(&Url) -> String`; `browser::listening(url: &Url, ended: &AtomicBool, pause: impl FnMut(Duration)) -> Option<bool>` (true listened, false gave up, None ended). `link::find(line: &str, offset: usize) -> Option<Link>` with `Link::Url { at: Range<usize>, url: String }` and `Link::File { at: Range<usize>, path: PathBuf, line: usize }`.

- [x] Acceptance tests: a wildcard host is `localhost` both ways; a non-http URL is no address; a stack frame's file and line are found at the caret and not away from it; a URL in a line is found whole; ANSI-free.
- [x] Implement and test as in Task 1.
