# Git Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for integration and superpowers:dispatching-parallel-agents for the independent core and text tasks. Track completed steps here.

**Goal:** Complete Phase 7's Git workflow, including rebase, conflict resolution and push.
**Architecture:** Git executable and models in core, pure comparisons in text, gpui controller and views in app.
**Tech Stack:** Rust 2024, gpui 0.2, installed Git, existing imara-diff.
**Spec:** `docs/superpowers/specs/2026-10-25-git-design.md`

## Global Constraints

- All subprocesses use core's Lifeline; no Git library or shell command construction.
- Preserve unrelated staged changes, file encoding and line separators. Use literal paths.
- Never block gpui on Git or diff computation. Reject stale replies.
- Reuse theme tokens, fonts, icons, dock, buffers, file writer and Local History.
- Commands are prefixed with rtk; commits use a message file.

## Review Focus

- Linked worktrees and opened subdirectories must refresh external Git state.
- Selected commits must leave unrelated staged content intact.
- Rebase Yours/Theirs must map to the correct index stage.
- Failed/stale resolutions must not overwrite external edits or silently clear conflicts.
- Large output, stderr and cancellation must leave typing and process cleanup working.

## Finishing pass

The run above stopped partway through Task 6. This pass finished it:

- `crates/rsharp-app/src/window/git.rs` would not compile: the `if`/`else` around a command's result had a stray
  `;`, so the crate never built after the last review fix. Fixed, and the workspace builds.
- `crates/rsharp-lsp/build.rs` read `dotnet msbuild`'s answer from stdout *and* stderr, so MSBuild's own
  "MSBuild server unavailable … Falling back to an in-process build" (stderr) was taken as the Roslyn folder
  whenever a machine cannot start MSBuild's server. It now parses stdout and keeps stderr for the failure message.
- The four regressions the review asked for are in `crates/rsharp-app/tests/git.rs`: a commit saves a buffer that
  lives beside the opened subfolder; leaving a workspace ends the Git work queued for it and drops its replies; a
  branch is checked out from the branch list by its full ref (remote refs track, local refs stay local); a conflict
  resolved in the merge window keeps the file's windows-1252 bytes.
- Large-file copies on the Git path are reduced: a revision's text is held with one copy (`hold_newlines`, shared
  with `Document::new`) instead of a `Document` and then its string, the working text of a comparison is turned
  into a string on the worker rather than the UI thread, and the gutter's own comparison stops at 4 MiB.
  `GitView` gains a `refs()` accessor and a `set_root`, so a change is listed by its path under the repository.
- The screenshots found three things the tests could not: change rows listed absolute paths and called an
  unversioned file "staged + unstaged", the branch controls were unreachable in a short Git island, and the bottom
  band of the dock let an island draw past the status bar. Fixed in `git_view.rs` and `window.rs`; the Commit and
  Log windows were captured again and look right.
- `ROADMAP.md` records Phase 7 in place with its limits, and `CLAUDE.md` describes the new modules and tests.
