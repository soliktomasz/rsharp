# Build and the Build Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, rebuild and clean the workspace or selected projects, with stoppable output and navigable diagnostics.

**Architecture:** Rust prepares and runs dotnet commands and parses their output. The existing Passenger Host coordinates generating design-time builds through a cancellable hold. A workspace-owned app controller feeds a dockable Build console and Problems' Build tab.

**Tech Stack:** Rust 2024, std process/threads/channels, existing regex/futures/serde, gpui 0.2.2, carried Passenger Host.

**Spec:** `docs/superpowers/specs/2026-10-24-build-design.md` (approved 2026-10-24).

## Global Constraints

- Every program starts through `rsharp_core::process::spawn`; no new dependencies expected.
- Non-UI crates have no gpui dependency; UI never blocks on processes or Host replies.
- Colours use existing `theme.rs` tokens; actions and keys follow Rider.
- Console text and pending output are bounded; diagnostic collection survives console eviction.
- Tests are offline, use isolated CLI homes/caches and cleared NuGet sources, and explain missing prerequisites.
- Shell commands start with `rtk`; commit messages go through a file; check disk space before long builds.

## Review Focus

1. Host failure during a held build must not start a replacement Host that writes generated files concurrently (Task 2).
2. Stop before process start and while output is backpressured must release every waiter and child (Tasks 1, 3).
3. Switching workspaces during build must discard old output and release the hold (Task 3).
4. A dirty file in a detached editor must be saved once, and a failed save must prevent launch (Task 3).
5. Paths with parentheses, drive letters or a relative project suffix must navigate to the right file (Tasks 1, 3).

### Task 1: Dotnet commands, output parsing and cancellable execution

**Files:** create `crates/rsharp-core/src/dotnet.rs`, `crates/rsharp-core/src/build.rs` and supporting focused modules if needed; export in `src/lib.rs`.

**Interfaces:** `dotnet::command(dotnet: &Path, args: impl IntoIterator<Item=impl AsRef<OsStr>>, folder: &Path) -> Command`; `dotnet::prepare(&mut Command)` sets CLI isolation. `build::Kind::{Build,Rebuild,Clean}`; `build::Problem` contains severity, message, code, optional path/project and zero-based line/column. `build::arguments(target: &Path, kind: Kind, windows_targeting: bool) -> Vec<OsString>`. `build::Parser::new(folder: PathBuf)`, `push(&str)`, `finish() -> Vec<Problem>`. `build::run(command: Command, cancel: &AtomicBool, output: impl FnMut(&str, bool)) -> io::Result<Option<i32>>` streams ANSI-free, UTF-8 text, where bool marks stderr and None means cancelled. App provides a bounded callback channel. The implementer may add `Output`/decoder helpers while preserving these interfaces.

- [ ] Add tests for exact command/environment, Windows and Unix diagnostic paths, multiline deduplication, incomplete UTF-8/ANSI and final lines; run to observe a failure.
- [ ] Implement the interfaces, concurrent pipe draining and cancellable whole-tree termination using existing Lifeline. Keep queue memory bounded and release children even when pipes remain open.
- [ ] Run `rtk cargo test -p rsharp-core` and confirm the new cases pass. Record one demonstrated regression failure before restoring the code.

### Task 2: Multiplex the Host and implement its hold

**Files:** modify `crates/rsharp-lsp/src/host.rs`; add focused Host tests; use Task 1's `dotnet::prepare`.

**Interfaces:** preserve existing `ProjectHost`/`SharedHost` build/evaluate/inspect APIs. Add `SharedHost::hold(cancel: &AtomicBool, waiting: impl FnMut(&[PathBuf])) -> Result<BuildHold, ServerFailed>`. `BuildHold::failed() -> Option<ServerFailed>` reports connection loss; dropping the guard cancels the hold. Pending/acquired holds pin the connection so other requests cannot silently replace it during the external build.

- [ ] Add a protocol fixture interleaving hold partials with ordinary replies, immediate cancellation, request errors and EOF; demonstrate a failure.
- [ ] Route replies by id on a reader thread; lock only complete writes and connection creation. Wake all pending callers on transport failure. Preserve partial-result semantics, including complete multi-target evaluations.
- [ ] Implement wait-until-held, cancellation and release, keeping the hold registered until its terminal reply. Ensure connection replacement is barred while a guard exists; request errors alone leave the connection usable.
- [ ] Run focused Host tests and live tests against an offline SDK fixture with a gated generating target; skip with a reason without dotnet/sidecars. Confirm a generating build waits until release, and a cancelled wait never leaks a hold.

### Task 3: Workspace build controller, console and navigation

**Files:** create `crates/rsharp-app/src/build_view.rs`, `src/window/build.rs`; modify `src/lib.rs`, `window.rs`, `workspace.rs`, `buffer.rs`, `dock.rs`, `actions.rs`, `keymap.rs`, `solution_menu.rs`, `window/solution_actions.rs`, `settings.rs`, `settings_dialog.rs`, `window/new_project.rs`, and `projects.rs` only where integration requires it.

**Interfaces:** MainWindow owns build output/entity, cancellation token, generation and immutable outcome; expose read-only `is_building()`, `build_output()`, `build_problems()` and `build_outcome()` for tests. Actions `BuildSolution`, `RebuildSolution`, `CleanSolution`, `BuildSelected`, `RebuildSelected`, `CleanSelected`, `ToggleBuild`, `StopBuild`. Build session consumes Tasks 1–2, saves deduplicated workspace buffers first, then holds the Host across the target queue. Output uses bounded futures channels and frame batches; late generations are ignored. `ProblemsTab::Build` and `Tool::Build` join existing exhaustive switches.

- [ ] Add window tests for Build from real keys, Problems navigation, rerun after fixing an unsaved error, Stop and action availability; demonstrate a failing test.
- [ ] Implement a selectable, copyable, read-only plain console with per-stream colours, source links, Rerun/Stop/Clear, scrolling and a 1024 KB retained buffer. Reuse existing text/editor selection where practical without C# parsing or language services.
- [ ] Implement target selection and off-thread discovery, queued execution, status/results navigation, cancellation on close/switch/drop, and Host failure handling. Save dirty workspace buffers across all windows by identity; reject failed saves.
- [ ] Add explicit-build opening and results settings with defaults true and Errors. Connect solution/project/folder commands and platform shortcuts to the same controller. Build once after New Solution attachment; leave Add New Project/opening existing workspace alone.
- [ ] Test the Review Focus cases, default/changed presentation settings, selecting project/folder targets, dock persistence and console eviction. Run focused window tests and correct any issues.
